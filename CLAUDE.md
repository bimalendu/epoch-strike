# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Epoch Strike is a 2D run-and-gun (20 levels and 20 bosses) written in plain HTML5 canvas and ES modules. It has **no runtime dependencies, no build step and no asset files** (the only dev dependencies are Playwright, for the browser tests, and Stryker, for mutation testing; neither reaches the shipped site). All graphics, sound effects and music are generated by code. Node >= 20 (CI uses 22).

**Read `docs/ARCHITECTURE.md` before changing anything.** It is the detailed reference for every subsystem (enemy archetypes, boss state machine, zones/hazards, music, art, perf, economy).

## Commands

    npm start                     # static server on http://localhost:8080 (PORT env overrides)
    npm test                      # full suite: node --test, ~10 s, nothing to install
    npm run coverage              # the same suite with a coverage floor on src/ (99 % lines, 94 % branches, 98 % functions); CI runs this
    npm run mutate                # mutation testing (Stryker) of the pure modules against tests/unit; minutes, by hand, never in CI. Report: reports/mutation/mutation.html
    npm run test:unit             # or test:integration / test:e2e: one layer (tests/unit, tests/integration, tests/e2e)
    npm run e2e                   # real browsers (Playwright; dev-only, needs `npm ci` and `npx playwright install`): chromium, firefox, webkit, mobile
    npm run e2e -- --project=chromium --grep @smoke   # just the smoke specs
    npm run e2e:update            # regenerate the visual baselines in tests/e2e/browser/__screenshots__
    node --test tests/integration/boss.test.js                                   # one file
    node --test --test-name-pattern="builder refuses" tests/integration/levels.test.js   # one test

Dev tools (all render headlessly through the software canvas):

    npm run shots                          # UI screenshots -> docs/screenshots
    npm run themeshots [dir] [theme...]    # one frame per era theme
    npm run levelshots <index> [dir] [x...]
    npm run bossshots <index> [dir] [scale] [style]   # style: ground | jump | ledge | under
    npm run musicwav [track|all] [dir] [loops]
    npm run perf [level [seconds]]         # sim time + canvas-call counts
    npm run economy                        # lives-economy model of the whole game

There is no linter or formatter configured.

## Architecture (big picture)

Layers, each depending only on the ones above it:

- `src/engine/`: canvas/`Painter`, font, RNG, input, audio and the music synth. Knows nothing about the game.
- `src/game/`: the simulation (`World`) and everything it owns. **No DOM access.**
- `src/game/art/`: procedural sprites, tiles, themes and HUD. Draws a `World` and never changes it.
- `src/scenes/`: glue between `Game`, `World` and the screen. Routes are in `scenes/routes.js`. Entry point: `src/main.js`.
- `tools/`: dev server, software canvas (`softcanvas.js`), PNG/WAV encoders, the player bots (`bot.js`, `bossbot.js`).

Core rules:
- Fixed 60 Hz step (`DT = 1/60`) at 480x270 logical pixels with 16 px tiles. `World.update(input, dt)` is deterministic: a seeded RNG means scripted input replays identically. Cosmetic randomness must come from `world.fxRand` and never from the gameplay RNG. A test checks that high and low effects quality produce identical simulations.
- The world never calls scenes. It pushes to `world.events` (`kill`, `levelClear`, `bossStart`, ...) and the scene drains them each frame.
- All art is rectangles drawn through `Painter`, so it renders identically in a browser and in Node's software canvas.
- Levels are scripts for `LevelBuilder` (`levelgen.js`), not grids. The builder throws on pits or steps the player can't cross. `solver.js` uses the real movement numbers to prove each level can be finished. Ground can slope: `b.slope(dh, { angle: 22 | 45 | 67 })` (67 is steep scree the soldier slides down and cannot climb); see "Slopes" in `docs/ARCHITECTURE.md`.
- Bosses are `arch: 'boss'` enemy defs run by the state machine in `boss.js` (enter -> idle -> tele -> attack, with phases). Boss scripts read arena bounds from `w.bossArena` and never from `level.boss` (Level 20 is a multi-arena boss rush).

### Registries
Every extensible list ends in a sentinel comment. Add new entries at the sentinel:

| Add a... | Edit | Sentinel |
| --- | --- | --- |
| level | `src/game/levels/lNN_*.js` + `levels.js` | `<<LEVEL_DEFS>>` |
| enemy (data / behaviour / sprite) | `enemy_defs.js` / `ai.js` / `art/enemies.js` (painters may live in `art/creatures.js` etc.) | `<<ENEMY_DEFS>>` / `<<ARCH>>` / `<<PAINTERS>>` |
| enemy or player bullet look | `art/ebullets.js` / `art/bullets.js` | `<<EBULLET_ART>>` / `<<BULLET_ART>>` |
| player weapon's gun sprite | `art/guns.js` | `<<GUN_ART>>` |
| boss | `bosses/<name>.js`, `bosses.js`, `art/bosses.js` (+ `art/bosses_wNN.js`) | `<<BOSS_IMPORTS>>`, `<<BOSSES>>`, `<<BOSS_PAINTERS>>` |
| player weapon | `weapons.js` | `<<WEAPONS>>` |
| music track | `tracks.js` | `<<TRACKS>>` |
| theme | `art/themes.js` | (object key) |
| theme's creatures, weather or foreground | `theme.life` / `theme.weather` / `theme.front` in `art/themes.js`; kinds in `art/life.js` (`CREATURES`), `art/weather.js`, `art/front.js` (`FRONT_KINDS`) | (object key) |
| landform, plant or sky painter for a parallax layer | `art/scenery_nature.js` (`NATURE`, `TREES`), layers listed in the theme | (object key) |
| ground fringe, underside or decor kind | `art/relief.js` (`FRINGES`, `UNDERSIDES`, `DECOR`), named by `theme.tiles.solid` and `theme.decor` | (object key) |

`enemy_defs.js` must not import `ai.js`. Hooks that need both live in `enemies.js`.

## Invariants the tests enforce
The suite runs the real game headlessly. Tests live in `tests/unit` (one module, synthetic input), `tests/integration` (a `World` or `Game` stepped with scripted input) and `tests/e2e` (whole-game journeys, the shipped files, the dev server). They import `tests/support/helpers.js`, which installs the software canvas and provides `makeInput`, `run(world, input, frames, keys, { keepSfx })` and `seconds()`; `tests/support/fixtures.js` holds shared builders (`spawnArena`, `makeStand`, `tap`, `bossIndex`). Expect failures if you break any of these:

- Every level is solvable. Every checkpoint and pickup is reachable. `tools/bot.js` crosses the level in god mode with zero falls and zero hazard touches.
- Every attack is telegraphed: enemy shots >= 0.5 s, dives >= 0.6 s, boss attacks >= `MIN_BOSS_TELE` (0.6 s). Hazard floor marks also take >= 0.6 s.
- With the rifle, `bossbot` must kill each real boss in 40-120 s with its phases in order, and the era weapon must make the fight shorter. The bot style per boss (`ground`/`jump`/`ledge`/`under`) is set in the tests' `STYLE` map.
- The enemy cap per era group (`enemyCapFor`) must be respected, including by arena waves.
- Perf budgets (`tests/integration/perf.test.js`): at most 2600 canvas calls in the busiest frame, and no canvas creation during play after warm-up. New lazy caches belong in `art/warm.js`. The life, weather and foreground of a theme together stay within 150 canvas calls a frame (`tests/integration/life_weather.test.js`).
- Slopes (`tests/integration/slopes.test.js`, `slope_levels.test.js`): every slope branch in `moveBody` is gated on `world.hasSlopes`, so a level without ramps simulates exactly as before. Zones that need level ground (`tankRoad`, `searchlight`, `flipHall`, `swells`, `barrage`, checkpoints) refuse a slope.
- Art uses no alpha for soft edges (dither instead, `dithered()` in `art/scenery_nature.js`): a test requires nature layers to be fully opaque, because the browser and the software canvas blend alpha slightly differently.
- Release (`tests/e2e/release.test.js`): the shipped site is only `index.html`, `style.css` and `src/`. Imports must be relative and stay inside `src/` (no bare specifiers). The README's level table must match the level registry.
- Economy (`tests/unit/economy.test.js`): one hidden 1UP per era group, 6-25 medals per level, and lives supply inside the break-even band. Changing a level's medals shows up here.
- The credits `BOSS_ORDER` must stay in step with the level scripts.
- Property tests use the game's own seeded `engine/rng.js`, so a failure replays exactly (the case number is in the message): save-file fuzz (`unit/save`), the keyboard model (`unit/input`), random builder courses against the solver and the bot (`integration/levels`), and random play for determinism (`integration/determinism`). Steps that follow each other add up (`up(3)` then `up(3)` is refused), but a pit straight after a step is judged separately: put ground between them.
- Dev tools (`tests/e2e/tools.test.js`): `shots`, `themeshots`, `levelshots`, `bossshots`, `musicwav`, `perf` and `economy` must run and write valid files, and `tests/e2e/browser/fixtures/parity.json` must match the software canvas (`npm run parity` regenerates it).
- Coverage floor on `src/` (`npm run coverage`): 99 % lines, 94 % branches, 98 % functions. Raise the numbers in `package.json` when coverage rises.

## Deployment
`.github/workflows/ci.yml` runs `npm run coverage` (job `test`: the suite plus the coverage floor, Node >= 22.8) and the Playwright suite (job `e2e`) on pushes to `main` and on PRs. `pages.yml` runs the tests, copies `index.html`, `style.css` and `src/` into `_site`, deploys to GitHub Pages, then runs the `@smoke` specs against the live URL (job `smoke`).
